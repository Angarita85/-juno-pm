## What "good" means

>=85% user validated recos, <=10% regeneration rate

-Active: User adjustments to prioritization, user validation of recommendations
-Passive: abandon rate, time-on-result

## The stack

| Layer | Evaluator | What it catches | Threshold / gate |
|---|---|---|---|
| Code-based | Automated checks · cadence: Every PR + nightly cron · owner: CI fails the PR. Eng  owns the format/citation. Product owns the accuracy bar. | - LLM judges accuracy of top 3 risks - format in markdown | >=90% response accuracy; 100% safety |
| LLM-as-judge | Automated assessment on the golden set | Silent wrong outputs at the long tail | >=90% response accuracy; 100% safety |
| Human | See -juno-pm/06-evals/human-rubric.md · 2 graders + PM breaks the tie · cadence: Weekly batch (Monday afternoon) | -100 P0 tickets -Bucketed into high, med, low confidence | >=4 is a pass across all dimensions.; 0 critical safety fails |

## Golden set

- 200 P0 anonymized threads to curate top 3 risks
- versioned in 06-evals/goldendataset
- revisted quarterly

## Release gate

**Hard gates (auto-block):**

- 0 critical safety issues
- Score of <3 for actionability
- Score of <4 for accuracy

**Soft gates (PM sign-off):**

Score of between 3 and 4 for actionability

**User-feedback layer (online):** cadence Per request; summarize weekly; owner PM owns validation score and acts to trigger recalibration.
